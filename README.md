# anvilkit-agent-contracts

The contract baseline of the AnvilKit Agent platform: the hand-maintained v1 sources of every service surface, the generated Go, TypeScript and Python consumers of those sources, the cross-runtime fixtures and the tools that generate and check them. The architecture that owns these contracts lives in the parent repository `anvilkit-services` (`docs/architecture/contracts.md`); this repository is consumed by the parent as the Git submodule `contracts/` and by each service as a versioned package.

## Layout

| Path | Content | Rule |
| --- | --- | --- |
| `proto/anvilkit/{control,knowledge,mcp}/v1/*.proto`, `buf.yaml`, `buf.lock` | Internal RPC contracts (Buf module `proto/`, protovalidate rules); `proto/messages.fixtures.json` holds the cross-runtime RPC vectors | Hand-maintained sources; Proto packages are `anvilkit.<domain>.v1`, field numbers are never reused |
| `openapi/{agent,model-proxy,inference}.yaml`, `openapi/*.fixtures.json`, `openapi/oapi-codegen*.yaml` | Public REST/SSE, Model Proxy transport and compute HTTP (OpenAPI 3.0.3) with their vectors and the oapi-codegen configurations | Hand-maintained sources; public JSON is not ProtoJSON |
| `jobs/`, `components/`, `events/` | Job envelope and profiles, component source contract, event envelope: JSON Schema 2020-12 with one `fixtures.json` each | Hand-maintained sources |
| `go/` | Go module `github.com/ancyloce/anvilkit-agent-contracts/go`: `anvilkit/<domain>/v1` (grpc-go), `agentapi` (Gin strict server + embedded spec), `modelproxyapi` (client + embedded spec), `jobschema` (verbatim schema copies + validator) | Generated by `tools/generate.py`, never hand-edited; released as the Go tag `go/vX.Y.Z` |
| `ts/` | `@anvilkit/generated-clients`: ts-proto/grpc-js bindings, `src/proto/descriptors.ts`, openapi-typescript types and the hand-written validation boundary `src/validation/{rpc,json}.ts` | Generated plus the one hand-written boundary; private package (no registry publication yet) |
| `python/` | `anvilkit-generated-clients`: pydantic v2 models of `openapi/inference.yaml` | Generated; installed in place by the tools |
| `tests/go/` | Go fixture-agreement tests of the generated module (kin-openapi, strict ProtoJSON + protovalidate) | Executable cases of the baseline |
| `tools/` | `generate.py [--check]`, `check.py [--against REF]`, `verify.py`, `verification-env.sh`, `requirements.txt` | The only generation and check entry points of this repository |

Nothing here reads a service or the parent repository. Service-owned generation (for example Control's sqlc output from its migrations) stays with the service that owns the schema.

## Generation and verification

```sh
sh tools/verification-env.sh                 # CPython 3.12 venv under .local/, then tools/verify.py: check, generate --check, go, ts, python
.local/verification-venv/bin/python tools/generate.py          # regenerate go/, ts/src/{proto,openapi}, python/ in place
.local/verification-venv/bin/python tools/check.py --against <git-ref>   # buf breaking against a recorded baseline of this repository
```

Pinned tools (verified by `tools/generate.py` before anything is generated): buf 1.73.0, protoc-gen-go 1.36.12, protoc-gen-go-grpc 1.6.2, oapi-codegen 2.8.0 (`go install` targets listed in `go/README.md`), ts-proto 2.12.3 and openapi-typescript 7.13.0 (through `pnpm-lock.yaml`, `pnpm install --frozen-lockfile`), datamodel-code-generator 0.81.0 and pydantic 2.13.5 (`tools/requirements.txt`). `tools/verify.py` runs the Go steps with `GOWORK=off`, so the checks never depend on an enclosing workspace.

What the checks establish: `check` — `buf lint`, OpenAPI validation, JSON Schema metaschema and fixture outcomes, the OpenAPI vectors of every surface, the message names of the RPC vectors; `generate --check` — the pinned generators reproduce every checked-in binding; `go` — the generated module builds and vets on its own and `tests/go` asserts every fixture outcome against it; `ts` — locked install, `tsc`, Biome and Vitest agreement with the same fixtures, including the validation boundary's decisions; `python` — pytest agreement with the inference vectors. They establish contract agreement only, not runtime behavior of any service.

## Consumers and versions

| Consumer | Package | How it is obtained |
| --- | --- | --- |
| `anvilkit-agent-api` (own repository) | `github.com/ancyloce/anvilkit-agent-contracts/go` | `require` of an explicit version (`go/vX.Y.Z` tag); no replace directive, no workspace |
| `anvilkit-agent-control`, `anvilkit-agent-workflow` (still inside `anvilkit-services`) | the same Go module | `require` of the same version; while they live in the parent checkout its `go.work` uses `./contracts/go` |
| Model Proxy, Knowledge, Background Worker, MCP TypeScript callers, the new Studio client (not started) | `@anvilkit/generated-clients` (`ts/`) | Not published; wired with their first consumer |
| Inference (not started) | `anvilkit-generated-clients` (`python/`) | Not published; wired with its first consumer |

Versioning: the sources are v1 contracts; the generated packages start at 0.1.0 (`go/v0.1.0`) and follow the compatible-evolution rules of the architecture (no reused field numbers, no reinterpreted enums; incompatible evolution needs an ADR and explicit consumer migration). A version is only obtainable once its tag exists on this repository's remote.
