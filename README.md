# anvilkit-agent-contracts

The contract baseline of the AnvilKit Agent platform: the hand-maintained v1 sources of every service surface, the generated Go, TypeScript and Python consumers of those sources, the cross-runtime fixtures and the tools that generate and check them. The architecture that owns these contracts lives in the parent repository `anvilkit-services` (`docs/architecture/contracts.md`); this repository is consumed by the parent as the Git submodule `contracts/` and by each component at the version or commit it pins (see [Consumers and versions](#consumers-and-versions)).

## Layout

| Path | Content | Rule |
| --- | --- | --- |
| `proto/anvilkit/{control,knowledge,mcp}/v1/*.proto`, `buf.yaml`, `buf.lock` | Internal RPC contracts (Buf module `proto/`, protovalidate rules); `proto/messages.fixtures.json` holds the cross-runtime RPC vectors; `proto/status-details.fixtures.json` the vectors of the one gRPC status detail defined outside the `.proto` files, the `google.rpc.ErrorInfo` of a Control revision conflict (reason `REVISION_CONFLICT`, domain `anvilkit.control.v1`, metadata `expectedRevision` and `currentRevision`), which Control and the API test against verbatim copies | Hand-maintained sources; Proto packages are `anvilkit.<domain>.v1`, field numbers are never reused |
| `openapi/{agent,model-proxy,inference}.yaml`, `openapi/*.fixtures.json`, `openapi/oapi-codegen*.yaml` | Public REST/SSE, Model Proxy transport and compute HTTP (OpenAPI 3.0.3) with their vectors and the oapi-codegen configurations | Hand-maintained sources; public JSON is not ProtoJSON |
| `jobs/`, `components/`, `events/` | Job envelope and profiles, component source contract, event envelope: JSON Schema 2020-12 with one `fixtures.json` each; `jobs/codegen/` the codegen Job's process protocol between its trusted supervisor and team coordinator (`urn:anvilkit:codegen-protocol:v1`, newline-delimited JSON over stdio, and the team result document) | Hand-maintained sources; the codegen protocol's consumers (`anvilkit-job-codegen-supervisor`, `anvilkit-job-codegen-team`) hold verbatim copies verified against it by their `tools/sync-protocol.sh --check`, and link no generated package of this repository (the jobs module embeds the profiles that pin their image) |
| `go/` | Go module `github.com/ancyloce/anvilkit-agent-contracts/go`: `anvilkit/<domain>/v1` (grpc-go), `agentapi` (Gin strict server + embedded spec), `modelproxyapi` (client + embedded spec), `jobschema` (verbatim schema copies + validator) | Generated by `tools/generate.py`, never hand-edited; released as the Go tag `go/vX.Y.Z` |
| `ts/` | `@anvilkit/generated-clients`: ts-proto/grpc-js bindings, `src/proto/descriptors.ts`, openapi-typescript types, verbatim copies of `jobs/{job.schema.json,profiles.json}` under `src/jobs/` and the hand-written validation boundary `src/validation/{rpc,json}.ts` | Generated plus the one hand-written boundary; private package, not published to a registry (consumers pin a commit) |
| `python/` | `anvilkit-generated-clients`: pydantic v2 models of `openapi/inference.yaml` | Generated; installed in place by the tools |
| `tests/go/` | Go fixture-agreement tests of the generated module (kin-openapi, strict ProtoJSON + protovalidate) | Executable cases of the baseline |
| `tools/` | `generate.py [--check]`, `check.py [--against REF]`, `verify.py [--only STEP ...]`, `verification-env.sh`, `requirements.txt`, and `pyenv_check.py` (the interpreter and dependency preflight the Python tools share) | The only generation and check entry points of this repository |

Nothing here reads a service or the parent repository. Service-owned generation (for example Control's sqlc output from its migrations) stays with the service that owns the schema.

## Generation and verification

```sh
sh tools/verification-env.sh                 # CPython 3.12 venv under .local/, then tools/verify.py: check, generate --check, go, ts, python
.local/verification-venv/bin/python tools/generate.py          # regenerate go/, ts/src/{jobs,proto,openapi}, python/ in place
.local/verification-venv/bin/python tools/check.py --against <git-ref>   # buf breaking against a recorded baseline of this repository
```

Pinned tools (verified by `tools/generate.py` before anything is generated): buf 1.73.0, protoc-gen-go 1.36.12, protoc-gen-go-grpc 1.6.2, oapi-codegen 2.8.0 (`go install` targets listed in `go/README.md`), ts-proto 2.12.3 and openapi-typescript 7.13.0 (through `pnpm-lock.yaml`, `pnpm install --frozen-lockfile`), datamodel-code-generator 0.81.0 and pydantic 2.13.5 (`tools/requirements.txt`). `tools/verify.py` runs the Go steps with `GOWORK=off`, so the checks never depend on an enclosing workspace.

What the checks establish: `check` — `buf lint`, OpenAPI validation, JSON Schema metaschema and fixture outcomes, the OpenAPI vectors of every surface, the message names of the RPC vectors, the status-detail vectors decided by the rule their file states; `generate --check` — the pinned generators reproduce every checked-in binding; `go` — the generated module builds and vets on its own and `tests/go` asserts every fixture outcome against it; `ts` — locked install, `tsc`, Biome and Vitest agreement with the same fixtures, including the validation boundary's decisions; `python` — pytest agreement with the inference vectors. They establish contract agreement only, not runtime behavior of any service.

## Consumers and versions

| Consumer | Package | How it is obtained |
| --- | --- | --- |
| `anvilkit-agent-api`, `anvilkit-agent-control`, `anvilkit-agent-workflow`, `anvilkit-agent-mcp`, `anvilkit-job-access-sidecar` (each its own repository) | Go module `github.com/ancyloce/anvilkit-agent-contracts/go` (`go/`) | `require` of an explicit tagged version (`go/vX.Y.Z`) in its `go.mod`, without a replace directive; in the parent checkout, `go.work` substitutes `./contracts/go` for workspace builds |
| `anvilkit-agent-model-proxy`, `anvilkit-agent-knowledge`, `anvilkit-agent-background-worker` | `@anvilkit/generated-clients` (`ts/`) | Git dependency pinned to a commit of this repository in its `package.json` (`github:ancyloce/anvilkit-agent-contracts#<commit>&path:ts`); never from a registry |
| `anvilkit-agent-inference` | `anvilkit-generated-clients` (`python/`) | Its image build copies `python/anvilkit_generated_clients` from a checkout of this repository given as the named build context `contracts`; its CI checks out that repository at a pinned commit |
| `anvilkit-job-parser` | `jobs/job.schema.json` | Copied into its image from the named build context `contracts`; CI checks out a pinned commit |
| `anvilkit-job-validator` | `components/component.schema.json`, `jobs/job.schema.json` and the validator profiles of `jobs/profiles.json` | Copied into its image from the named build context `contracts`; CI checks out the commit of its `CONTRACTS_REF` |
| `anvilkit-job-codegen-supervisor`, `anvilkit-job-codegen-team` | `jobs/codegen/` (the process protocol) | Verbatim copies checked by their `tools/sync-protocol.sh --check` (see Layout) |

The README of each Go and TypeScript consumer states the version or commit its manifest pins in a block that the parent's `tools/docs-status.py` generates; the manifests are the authority.

Versioning: the sources are v1 contracts and follow the compatible-evolution rules of the architecture (no reused field numbers, no reinterpreted enums; incompatible evolution needs an ADR and explicit consumer migration). The Go module is released as `go/vX.Y.Z` tags from `go/v0.1.0` on; the TypeScript and Python packages keep version 0.1.0 and are consumed by commit. A Go version is only obtainable once its tag exists on this repository's remote, and a commit only once it is pushed there.
